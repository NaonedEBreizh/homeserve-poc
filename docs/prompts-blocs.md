Règles de la séance : un bloc = un prompt = un commit. Le product owner lance le chrono au bloc 1 et arbitre les **points d'arrêt** à 0:40 (fin du bloc 3) et 1:10 (fin du bloc 5). ## Bloc 2 — 0:10 → 0:25 · Moteur solaire

> **Bloc 2.** Implémente `engine/solaire.ts` pour faire passer `test/engine/solaire.test.ts`, sans modifier le test. Types exportés : `EntreesSolaire`, `OptionsSolaire { tauxHausse?, horizon?, stockage?: 'aucun'|'virtuel'|'batterie', kwc?: 3|6|9, couplagePac?: boolean }`, `SolaireResult`, `Projection`. Règles : facture annuelle par tranche (`hypotheses.tap.facture_annuelle_par_tranche`) ; TAP = clamp(base(zone, tranche surface) + Σ bonus/malus, 12, 63) avec `data/tap-base.json`, `data/zones.json` (dept → zs) et `hypotheses.tap.bonus_malus_points` ; borne sans véhicule = véhicule implicite ; couplage PAC : le malus −9,2 devient +3,0 ; TAP batterie = min(TAP + 21, 84) ; économies = round(facture × TAP/100) ; kWc conseillé par la règle `kwc_conseille` ; prix du pack ; production = kWc × productible du département ; surplus = production × (1 − TAP/100) × prix surplus ; reste à charge = prix pack (aides solaire = 0 en 2026) ; retour = reste / (économies + surplus) ; `horsZone` si `zones[dept].eligible === false` ; erreur si département inconnu. `projeter()` : deux conventions, `homeserve` (N années, facture et économies inflatées au même taux, arrondi `Math.ceil` annuel, cumul sur N termes) et `edf` (N+1 incréments, cumul N+1 termes) ; `annees` de 0 à N. Aucune dépendance React. Commit « feat: moteur solaire + projection ».
